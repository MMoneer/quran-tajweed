# تشخيص وإصلاح تداخل التشكيل مع الحروف

## المشكلة

عند عرض النص القرآني بخط Uthmanic Hafs، تظهر بعض حركات التشكيل (الضمة، الفتحة، الألف الصغيرة، المدّة، إلخ) متداخلة مع الحروف بدلاً من أن تكون في موضعها الصحيح فوق الحرف.

### أمثلة على الكلمات المتأثرة

| الكلمة | المشكلة |
|--------|---------|
| **يُوقِنُونَ** | الضمة على النون متداخلة |
| **يُنفِقُونَ** | الضمة على القاف متداخلة |
| **ٱلْكِتَـٰبُ** | الألف الصغيرة متداخلة مع التاء |
| **رَّزَقْنَٰهُمُ** | الألف الصغيرة متداخلة مع النون |
| **زَكَرِيَّآ** (سورة مريم، آية 2) | المدّة (ٓ) متداخلة مع الألف |
| **بَآءً** | المدّة (ٓ) متداخلة مع الألف |

## الأسباب

### 1. تعطيل ميزات OpenType في CSS

السطر `font-feature-settings: "calt" 0` في `.verses-display-area` كان يُعطّل:
- **`calt`** (Contextual Alternates) — البدائل السياقية التي يحتاجها الخط لوضع التشكيل
- قد يؤثر تعطيل `calt` على تفعيل `mark` و `mkmk` تلقائياً في بعض المتصفحات

**الملف:** `css/styles.css:1360`

### 2. فصل حركات التشكيل عن حروفها الأصلية في mergeTajweedToQPC

في دالة `mergeTajweedToQPC`، عندما تختلف قاعدة التجويد للحرف عن قاعدة حركة التشكيل التي تليه، تنشأ مشكلة:

```
مثال: في "يُنفِقُونَ"
القاف (ق) ← لا توجد قاعدة تجويد
الضمة (ُ) ← لها قاعدة madda_permissible
الواو (و) ← لها قاعدة madda_permissible
```

الخوارزمية القديمة كانت تُخرِج:
```html
ق<tajweed class="madda_permissible">ُو</tajweed>
```
الضمة في عنصر منفصل عن القاف ← الخط لا يعرف أين يضعها ← تتداخل.

لأن حركات التشكيل (Unicode combining marks) يجب أن تبقى في نفس عنصر HTML مع الحرف الأصلي كي يعمل محرك الخط (HarfBuzz) بشكل صحيح.

**الملف:** `js/pageRenderer.js:29-100`

### 3. فصل المدّة (U+0653) عن حروف المد في wrapNormalMadd

في دالة `wrapNormalMadd`، الـregex القديم كان يضع حرف المد (ا، و، ي) داخل `<tajweed class="madda_normal">` لكنه كان يترك المدّة `ٓ` (U+0653 - ARABIC MADDAH ABOVE) خارج العنصر.

```
مثال: في "زَكَرِيَّآ" (سورة مريم، آية 2)
```

الـregex القديم:
```javascript
.replace(/َا(?![ًٌٍَُِّْ])/g, 'َ<tajweed class="madda_normal">ا</tajweed>')
```

الناتج القديم:
```html
زَكَرِيَّ<tajweed class="madda_normal">ا</tajweed>ٓ
```

المدّة (`ٓ`) مفصولة عن الألف (`ا`) في عنصر HTML مختلف ← HarfBuzz لا يستطيع وضع المدّة فوق الألف ← تتداخل المدّة في الألف.

**الملف:** `js/pageRenderer.js:260-297`

## الإصلاح

### الإصلاح 1: تفعيل ميزات OpenType في CSS

```css
/* قبل (معطل) */
font-feature-settings: "calt" 0;

/* بعد (مفعل) */
font-feature-settings: "calt" 1, "mark" 1, "mkmk" 1, "kern" 1;
```

**التغيير:** `css/styles.css:1360`
- إزالة `"calt" 0`
- إضافة تفعيل صريح لـ `calt`, `mark`, `mkmk`, `kern`

### الإصلاح 2: منع فصل التشكيل عن الحرف في mergeTajweedToQPC

**قبل:**

```javascript
// js/pageRenderer.js السطر 85
while (i < qpcResult.length && qpcResult[i].rule === rule) {
```

**بعد:**

```javascript
// js/pageRenderer.js السطر 85
while (i < qpcResult.length && (qpcResult[i].rule === rule || isDiacritic(qpcResult[i].char))) {
```

ونفس المنطق للحالة الثانية (بدون قاعدة):

```javascript
// js/pageRenderer.js السطر 93-96
while (i < qpcResult.length && isDiacritic(qpcResult[i].char)) {
```

**المنطق:** أي حرف تشكيل (diacritic) لا يبدأ عنصر HTML جديد أبداً. الحركة تلتصق بالعنصر الذي يسبقها (سواء كان `<tajweed>` أو نص عادي).

### الإصلاح 3: إبقاء المدّة مع حرف المد في wrapNormalMadd

**قبل:**

```javascript
// js/pageRenderer.js السطر 276-278 (الإصدار القديم)
const parsedText = text
  .replace(/َا(?![ًٌٍَُِّْ])/g, 'َ<tajweed class="madda_normal">ا</tajweed>')
  .replace(/ُو(?![ًٌٍَُِّْ])/g, 'ُ<tajweed class="madda_normal">و</tajweed>')
  .replace(/ِي(?![ًٌٍَُِّْ])/g, 'ِ<tajweed class="madda_normal">ي</tajweed>');
```

الناتج القديم لـ `زَكَرِيَّآ`:
```html
زَكَرِيَّ<tajweed class="madda_normal">ا</tajweed>ٓ  ← ٓ خارج العنصر
```

**بعد:**

```javascript
// js/pageRenderer.js السطر 276-278 (الإصدار الحالي)
const parsedText = text
  .replace(/(َ)ا(ٓ?)(?![ًٌٍَُِّْ])/g, '$1<tajweed class="madda_normal">ا$2</tajweed>')
  .replace(/(ُ)و(ٓ?)(?![ًٌٍَُِّْ])/g, '$1<tajweed class="madda_normal">و$2</tajweed>')
  .replace(/(ِ)ي(ٓ?)(?![ًٌٍَُِّْ])/g, '$1<tajweed class="madda_normal">ي$2</tajweed>');
```

الناتج الجديد لـ `زَكَرِيَّآ`:
```html
زَكَرِيَّ<tajweed class="madda_normal">آ</tajweed>  ← المدّة داخل العنصر مع الألف
```

**المنطق:** المدّة (U+0653 `ٓ` - ARABIC MADDAH ABOVE) هي حرف تشكيل مركّب (combining mark) ويجب أن تبقى في نفس عنصر HTML مع حرف المد (ا، و، ي) الذي تظهر فوقه. الـregex الجديد يلتقط المدّة الاختيارية `(ٓ?)` ويضعها داخل عنصر `<tajweed>` مع حرف المد.

هذا الإصلاح ينطبق على جميع حروف المد الثلاثة:
- **الألف**: `َآ` ← `َ<tajweed class="madda_normal">آ</tajweed>`
- **الواو**: `ُوٓ` ← `ُ<tajweed class="madda_normal">وٓ</tajweed>`
- **الياء**: `ِيٓ` ← `ِ<tajweed class="madda_normal">يٓ</tajweed>`

### التعريف بحروف التشكيل

الدالة `isDiacritic` في `js/pageRenderer.js:48-53` تعرّف حروف التشكيل على أنها:

```javascript
function isDiacritic(ch) {
  const code = ch.charCodeAt(0);
  return (code >= 0x064B && code <= 0x0658) ||    // التشكيل الأساسي (فتحة، ضمة، كسرة، شدّة، سكون، مدّة ٓ U+0653...)
         code === 0x0670 ||                         // الألف الصغيرة (ٰ)
         code === 0x06E1 ||                         // رأس الخاء المنقط (ۡ - السكون في الرسم العثماني)
         (code >= 0x06D6 && code <= 0x06ED);       // علامات القرآنية الإضافية
}
```

**ملاحظة مهمة:** المدّة `ٓ` (U+0653) تقع ضمن نطاق `0x064B–0x0658` وبالتالي تُعتبر `isDiacritic = true`. لكنها **لا** تقع ضمن `isHarakah` (التي تغطي `0x064B–0x0652` فقط)، وهذا صحيح لأن المدّة ليست حركة إعرابية.

## كيفية التحقق من جميع الإصلاحات

### الإصلاح 1 و 2 (OpenType + mergeTajweedToQPC)
1. افتح سورة البقرة (`#surah/2`)
2. ابحث عن الكلمات التالية وتحقق من عدم التداخل:
   - **الآية 2:** ٱلْحَمْدُ لِلَّـهِ رَبِّ ٱلْعَـٰلَمِينَ — الألف الصغيرة على العين
   - **الآية 3:** يُنفِقُونَ — الضمة على القاف
   - **الآية 4:** يُوقِنُونَ — التشكيل عامة
   - **الآية 2:** ٱلْكِتَـٰبُ — الألف الصغيرة على التاء
   - **الآية 3:** رَّزَقْنَٰهُمُ — الألف الصغيرة بعد النون

### الإصلاح 3 (المدّة مع حروف المد)
1. افتح سورة مريم (`#surah/19`)
2. تحقق من الكلمة **زَكَرِيَّآ** في الآية 2 — يجب أن تظهر المدّة فوق الألف بوضوح، غير متداخلة
3. ابحث عن كلمات أخرى فيها مدّة فوق حرف مد:
   - سورة البقرة: `بَآءً`, `شَآءَ`
   - سورة آل عمران: `جَآءَ`
4. كرر الاختبار بأحجام خط مختلفة (من 20px إلى 60px)
5. اختبر في المتصفحات المختلفة (Chrome, Firefox, Edge)

## ملاحظات إضافية

- إذا ظهرت المشكلة مجدداً، تحقق أولاً من:
  1. وجود `"calt" 0` في CSS — أزله
  2. عدم وجود `font-feature-settings` معطِّل لميزات OpenType الأخرى
  3. أن دالة `mergeTajweedToQPC` لا تضع التشكيل في عناصر منفصلة
  4. أن دالة `wrapNormalMadd` لا تفصل المدّة `ٓ` عن حرف المد
- خط Uthmanic Hafs (V22) يعتمد على ميزات OpenType القياسية لوضع التشكيل
- الألف الصغيرة (U+0670) هي حرف تشكيل مركّب (combining mark) ويجب معاملتها مثل باقي التشكيل
- المدّة (U+0653 `ٓ`) هي حرف تشكيل مركّب (combining mark) ويجب أن تبقى في نفس عنصر HTML مع حرف المد الذي تظهر فوقه
- الاستثناء: بعض الحركات قد تفقد لون قاعدة التجويد الأصلي إذا كانت قاعدتها مختلفة عن الحرف، وهذا مقبول لأن Positioning أهم من Coloring

## قائمة المراجعة الكاملة لضمان دقة عرض التشكيل

عند فحص عرض النص القرآني، تأكد من النقاط التالية:

- [ ] `font-feature-settings` لا يحتوي على `"calt" 0` في CSS
- [ ] `font-feature-settings` يتضمن `"calt" 1, "mark" 1, "mkmk" 1, "kern" 1`
- [ ] التشكيل الأساسي (فتحة، ضمة، كسرة) لا يبدأ عنصر HTML جديد أبداً (الإصلاح 2)
- [ ] الألف الصغيرة (U+0670 `ٰ`) لا تبدأ عنصر HTML جديد أبداً (الإصلاح 2)
- [ ] المدّة (U+0653 `ٓ`) لا تنفصل عن حرف المد في `wrapNormalMadd` (الإصلاح 3)
- [ ] جميع combining marks ضمن نطاق `isDiacritic` تُعامل بشكل صحيح
